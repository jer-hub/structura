# 11: Instructor report combiner

**What to build:** An instructor downloads every student's Progress Report from a Google Classroom assignment into one folder and runs a single command that produces one CSV spreadsheet: one row per student per Puzzle (student name, student ID, Zone, Puzzle, Stage, Stars, Moves, Reference Solution Moves, Glitches, Hints, attempts, completed date) plus a "verified" column. A report whose signature doesn't verify is still included but flagged, and a file that isn't a Progress Report is skipped with a warning. It runs from source and needs no GUI. Usage is documented for faculty.

**Blocked by:** 14 (A malformed Progress Report is reported as unverified instead of crashing)

## Comments

- `python -m structura.combine <folder> <out.csv>`, also installed as `structura-combine`. Code in `src/structura/combine.py`, tests in `tests/test_combine.py`, faculty guide in `docs/combining-progress-reports.md` (linked from the recommended syllabus).
- Tests use reports exported by the game's own `report.export`; the "newest report" test pins the export clock so only `generated_at` can decide which report is newer.
- Behaviour beyond the checklist, each test-first:
  - Subfolders are searched, since a Google Classroom download may be nested.
  - The CSV is UTF-8 with a byte-order mark so Excel shows names like "Peña" correctly.
  - Names and other text a spreadsheet would run as a formula (`=`, `+`, `-`, `@`…) get a leading `'`.
  - An edited report with text UTF-8 can't encode is still included, with that text shown as "?".
  - Unreadable or absurdly nested JSON is skipped, not a crash.
  - If the CSV can't be written (usually because it's open in Excel), the command says so and nothing is half-written.
- If a student's newest report fails verification, it is still the one used (flagged), even if an older verified one exists. The instructor follows up either way.
- "Report combiner" is the spec's name for this tool but isn't in `CONTEXT.md`; a candidate for the glossary.
